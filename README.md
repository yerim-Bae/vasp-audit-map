# 국내 VASP 사업·회계 지도 (Crypto Audit Map)

**사이트:** https://yerim-accounting.vercel.app/vasp-map/

금융정보분석원(FIU)에 신고된 국내 가상자산사업자(VASP) 45곳의 신고 현황, DART 감사보고서, 가상자산 회계정책 주석, 재무 수치, 감사위험을 한 화면에 엮은 리서치 프로젝트입니다.
감사보고서를 처음 받아 드는 신입 회계사가 "이 회사는 어떻게 돈을 벌고, 고객 자산을 어떻게 맡아 두며, 그것을 장부에 어떻게 잡는가"를 30분 안에 파악하는 것을 목표로 했습니다.

## 무엇이 다른가

- **원문·요약·분석을 분리합니다.** 감사보고서에서 그대로 발췌한 문장(접수번호·DART 링크 포함), 그것을 읽고 정리한 요약, 그리고 제 분석적 추론을 데이터 필드와 화면 모두에서 구분합니다. 확인하지 못한 값은 0이 아니라 `null`·"확인되지 않음"으로 둡니다.
- **회사마다 다른 회계처리를 나란히 놓습니다.** 두나무(K-IFRS, 무형자산)와 빗썸·코인원·코빗·고팍스(일반기업회계기준, 공정가치 평가)가 고객 위탁 가상자산을 미인식한다는 같은 결론에 다른 근거로 이르는 과정을 비교표로 보여줍니다.
- **검토 중인 항목을 숨기지 않습니다.** 법인 매칭 실패, 원문에 없는 주석, 시드와의 불일치는 `data/needs-review.json`에 남기고 사이트에도 배지로 표시합니다.

## 원문에서 확인한 것 중 눈에 띄는 사실

- 코빗은 회원 위탁 가상자산을 회사 소유분과 같은 전자지갑에 **혼합 보관**한다고 3개년 연속 공시합니다. 다른 4개사는 분리보관을 서술합니다.
- 코빗의 **투자가상자산**(제3자 대여·운용)은 2024년 710억원, 2025년 462억원으로 자기 보유분보다 큽니다.
- 해킹 대비 방식이 갈립니다. 두나무·코인원·빗썸은 이용자보호준비금, 고팍스는 배상책임보험(부보 39억원, 위탁 자산 1,646억원 대비 약 2.4%)입니다.
- 코빗의 관계기업에 보관관리업자 KDAC(한국디지털자산수탁)이 있습니다.
- 고객 위탁 가상자산의 주석 시가(2025년 말): 두나무 62.2조원, 빗썸 17.9조원, 코인원 2.7조원, 코빗 1.6조원, 고팍스 1,646억원. 다섯 곳 모두 재무제표에는 계상하지 않습니다.

## 감사절차 가이드 페이지

한국공인회계사회 「가상자산에 대한 감사 가이드라인」(2023.12 공표)의 절별 원문 발췌(문단·쪽 표기)에 이 사이트의 회사 사례를 연결한 페이지입니다. 데이터는 `data/audit-guideline.json`, 원문은 `docs/references/`. 감사 단계 보기와 가이드라인 목차 보기 두 가지로 볼 수 있고, 사업자·보유 기업·발행 기업으로 거를 수 있습니다. 발행 기업 절(문단 57~60)의 사례를 위해 FIU 명단 밖의 상장사 4곳을 추가했습니다.

## 방법론

1. **명단**은 FIU 공식 자료(2026-08-31 기준)만 씁니다. 언론이나 과거 명단으로 현재 상태를 판단하지 않습니다.
2. **법인 매칭**은 DART 기업개황의 사업자등록번호가 FIU 사업자등록번호와 일치할 때만 `exact`. 이름만 비슷하면 연결하지 않습니다. 미갱신 사업자 5곳은 2024-07-30 명단의 사업자번호로 확정했고, 동명 법인 1곳은 불일치로 미등록 처리했습니다(`docs/IDENTITY_CHECK.md`).
3. **감사의견·감사인·계속기업 문구**는 DART 원문(document.xml)에서 확인한 것만 기록하고 플래그를 남깁니다.
4. **금액**은 원 단위 정수로 통일하고 원문 단위와 계정명을 함께 보존합니다. 연결과 별도는 섞지 않습니다.
5. **기준 틀**은 금융위·금감원 「가상자산 회계처리 감독지침」(2023.12) 원문 Ⅲ-4(사업자) 절을 직접 대조했습니다(`docs/ACCOUNTING_FRAMEWORK.md`, `docs/references/`).

자세한 과정과 판단 기록은 `PROGRESS.md`, `README-data.md`, `docs/`에 있습니다.

## 만든 과정

데이터 수집(DART API 호출, 원문 파싱, 1차 추출)은 AI 코딩 도구(Codex, Claude Code)로 자동화했고, 회계 판단이 필요한 항목(계정 정의, 법인 동일성, 회사 고유 위험의 선별, 원문 대조)은 제가 직접 확인했습니다. 어느 값이 원문 확인이고 어느 값이 추론인지는 데이터의 `confidence`·`status`·`scope` 필드에 남아 있습니다. `docs/process/`에 실제 사용한 작업지시문을 그대로 두었습니다.

## 사이트 소스

`site/`는 Vite + React 정적 앱입니다. `data/`를 직접 읽습니다.

```bash
cd site && npm install && npm run build
```

빌드 결과(`site/dist`)를 개인 사이트의 `vasp-map/`에 복사해 배포합니다.

## 한계와 주의

- 45곳 중 감사보고서를 깊게 확인한 법인은 6곳입니다. DART에 없는 30곳은 명단·신고상태·링크만 있습니다.
- "분석"으로 표시된 내용은 감사보고서에 직접 기재된 사실이 아니라 공개 자료를 바탕으로 한 개인 의견이며, 특정 회사에 대한 평가나 투자 판단의 근거가 아닙니다.
- 기준일은 FIU 명단 2026-08-31, 감사보고서 FY2025까지입니다.
