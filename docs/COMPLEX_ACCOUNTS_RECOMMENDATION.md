# 복합 계정 4개 — 회사별 추천안 (2026-09-07, 승인 대기)

> 검토표 3번의 결정을 쉽게 하려고 감사보고서 원문에서 **실제 금액과 표 위치**를 뽑았다.
> 표의 숫자는 원문 그대로(단위 표시). 정의(어느 필드에 무엇을 넣을지)는 제 제안이므로 바꾸어도 된다.
> 승인하면 `financials.json` 에 넣는 작업은 스크립트로 10분이면 끝난다. 데이터는 아직 바꾸지 않았다.

## 1. 필드 정의 제안

| financials 필드 | 넣을 값 | 이유 |
|---|---|---|
| `crypto_assets_owned` | 재무상태표에 계상된 회사 소유 가상자산 장부금액 (코빗은 가상자산 + 투자가상자산 합, 두나무는 무형자산 중 가상자산) | 회사마다 계정명이 달라도 "회사 자산으로 인식한 금액" 으로 통일 |

| `customer_deposits` | 재무상태표 부채의 원화 예치금 (회원예치금 / 예수금 / 고객예수부채 / 예수부채) | 계정명은 `original_account_name` 에 보존 |
| `financial_assets` | 보류 (회사별 범위가 너무 달라 이번 결정에서 제외) | 두나무는 FVPL·AC·FVOCI 세 줄, K-GAAP 사들은 단기금융상품·매도가능증권 등 |

## 3. 승인 시 할 일 (제가 처리)

1. 위 표를 `financials.json` 의 해당 레코드 `figures` 에 넣는다. 단위는 원으로 환산(천원 × 1,000), `original_unit`·`original_account_name`·`note_number` 기록.
2. `customer_crypto_liabilities` 는 전부 null + notes.
3. 2023 년의 "확인 필요" 칸은 원문을 열어 채우거나 null 로 둔다.
4. `needs-review.json` 의 `financial_complex_accounts` 를 resolved 로 바꾸고 결정 내용을 notes 에 적는다.
5. `validate.py` 실행(자산 = 부채 + 자본 검사는 이 필드와 무관하므로 통과 예상).
